# loopio-library-2 — working setup

Confirmed working 2026-09-02.

## Usage
    cd ~/Desktop/pinecone-loopio
    python3 query.py "your question" [topK]

## Config that matters
- Index host: loopio-library-2-rme8ns3.svc.aped-4627-b74a.pinecone.io
- Namespace: "" (empty string) — NOT "__default__"
- Vectors: 1,509 | 1536-dim | cosine | dense
- Embeddings: OpenAI text-embedding-3-small, generated externally.
  The index has no integrated embedding model, so queries must supply
  a vector. Pinecone MCP text search does not work on this index.
- OpenAI host: us.api.openai.com — our org enforces US data residency,
  so keys are rejected on api.openai.com with 401 incorrect_hostname.

## Three blockers that had to be cleared
1. Egress allowlist: api.openai.com + the Pinecone index host (403 at proxy).
2. OpenAI credits exhausted (429 insufficient_quota).
3. Regional hostname: us.api.openai.com added to the allowlist.

## Record shape (metadata)
question, answer_plain, stack_name, tags, last_updated_date

Full source text lives in metadata, so the library is recoverable from the
index itself — no Loopio re-export needed for a rebuild.

## Known data issue
Records are duplicated across the "Client Strategy" and
"Client Strategy- Cleaned" stacks: identical answer text, different
last_updated_date and tags. Every result set returns each answer twice.
Dedupe on question+answer keeping the newest last_updated_date.

## Longer-term option
Rebuild via create-index-for-model (integrated embedding, llama-text-embed-v2,
1024-dim). Text queries would then work natively through the Pinecone MCP with
no OpenAI dependency, no credits and no allowlist entries. Existing 1536-dim
vectors are not portable — re-embed from the metadata text.
